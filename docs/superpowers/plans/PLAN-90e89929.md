### TASK-006: Write mode-a/implement-verify.md prompt file

- Define role: main agent orchestrates topology-sorted parallel subagent implementation
- This is the largest prompt — encode the full 5-round implement-verify loop:
  - Round 1: Read PLAN, analyze dependency graph, dispatch parallel Haiku subagents per task (TDD), review each, loop on failure
  - Round 2: Run `{test_command}`, collect failures, decompose into fix tasks, repeat
  - Max 5 rounds, monotonic convergence check, pause for human if violated
  - Verification phase: for each acceptance criterion (IDENTIFY / RUN / READ / VERIFY / CLAIM), generate `docs/evidence/EVIDENCE-{run_id}.md`, set `review_implement_verify_passed`
- Include gate references: `command_success:{test_command}`, `file_exists:docs/evidence/EVIDENCE-{run_id}.md`
- File path: `.devflow/prompts/mode-a/implement-verify.md`

## Test Strategy

- **Unit tests** (`tests/test_config.py`): No changes expected. Run as-is to verify no regression.
- **Unit tests** (`tests/test_workflow_engine.py`): May contain hardcoded references to old step IDs (`implement-sdd`, `code-review`, `test-run`, `verify`). Update these to `implement-verify` in TASK-024. Run after fixture updates to confirm.
- **E2E integration tests**: Six fixture TOML files updated in TASKS-018 through 023. E2E tests exercise MODE-A and MODE-B workflows end-to-end. After fixture update, they must load, parse, and step through the new 6-step / 7-step structures without engine errors.
- **Validation** (`devflow validate`): Checks workflow file parseability, prompt file existence, and test command configuration. Run as final gate in TASK-026.
- **No engine code changes**: `gate_checker.py`, `workflow_parser.py`, `workflow_engine.py`, `config.py`, `state_store.py` are untouched. All changes are in prompts, TOMLs, and test fixtures.
