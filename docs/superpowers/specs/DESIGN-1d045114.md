## Context

Three targeted fixes identified during codebase audit. Each is independent and low-risk.

## Approach A: Incremental Fix (Recommended)

Fix each issue individually with minimal surface area.

### Fix 1: Unknown Gate → Fail
- Change `gate_checker.py:259`: `return True` → `return False`
- One-line change, zero API impact
- **Risk**: negligible — only affects malformed gate strings
- **Trade-off**: gate typos that previously passed now correctly block

### Fix 2: AdvanceResult Dataclass
- Add `AdvanceResult` to `workflow_engine.py`:
  ```python
  @dataclass
  class AdvanceResult:
      advanced: bool
      current_step: Step | None
      message: str
      is_complete: bool = False
  ```
- Update 3 callers: `cli.py`, `loop_engine.py`, test files
- **Risk**: low — mechanical refactor, same data, explicit naming
- **Trade-off**: slightly more verbose than tuple destructuring, but eliminates string-matching fragility

### Fix 3: Config.version Default
- Change `config.py:21`: `"0.1.5"` → `""`
- One-line change
- **Risk**: none — empty string is a safe default; the release script already syncs versions
- **Trade-off**: downstream code that relied on the old default will get `""` — but that code shouldn't exist because the value was never meaningful

### Implementation Order
1. Fix 3 (config.py) — simplest, warm-up
2. Fix 2 (AdvanceResult) — mechanical refactor with test updates  
3. Fix 1 (gate_checker.py) — final security fix

## Approach B: Combined Result Type + Gate Fix

Bundle all changes into a single refactor pass. Saves commits but makes review slightly harder.

**Verdict**: Rejected. Independent fixes should be independently verifiable.

## Recommendation

**Approach A** — three independent, incremental changes. Each is verifiable by tests, none depend on each other. Standard TDD: update tests first where interfaces change, then implement.
