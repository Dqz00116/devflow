## Technical Approach

### 1. Fix Unknown Gate Silent Pass (`gate_checker.py`)

**Current**: `check_gate()` line 259 — unknown gate types return `(True, msg)`, meaning typos like `file_exist:path` pass without error.

**Change**: Return `(False, msg)` for unknown gates. This is the safe default — a gate the system doesn't understand should block, not pass.

**Impact**: Minimal. This only affects malformed gate strings. If a project has a typo in a gate, it will now correctly block instead of silently passing.

### 2. Refactor advance() Return Type (`workflow_engine.py`)

**Current**: `advance() -> tuple[bool, Step | None, str]` where:
- `(True, step, msg)` = advanced or routed on failure
- `(False, None, msg)` = no current step / workflow complete / resolution error  
- `(False, step, msg)` = gates failed, stay on step

Caller in `cli.py:445` uses `"complete" in msg.lower()` to detect completion — fragile.

**Change**: Introduce `AdvanceResult` dataclass with explicit fields:
```python
@dataclass
class AdvanceResult:
    advanced: bool          # Did we move to a new step?
    current_step: Step | None
    message: str
    is_complete: bool       # Explicit instead of string matching
```

**Impact**: 
- `workflow_engine.py` — change return type of `advance()`
- `cli.py:443-455` — destructure result type instead of tuple
- `loop_engine.py:151` — destructure result type instead of tuple
- Tests — update destructuring patterns

### 3. Fix Config.version Default (`config.py`)

**Current**: `ProjectConfig.version: str = "0.1.5"` — hardcoded to DevFlow tool version, confusing for user projects.

**Change**: Default to `""` (empty string). The release script will continue to sync the correct version for DevFlow itself, and user projects won't get a misleading default.

**Impact**: 
- `config.py` line 21 — one-line change
- Verifies release script `VERSION_SOURCES` still works (it reads the field, not hardcodes)
