## Description

Refactor MODE-A and MODE-B workflows to adopt an architect/subagent execution model where the main agent handles only design, planning, and review, while all operational actions are delegated to parallel Haiku subagents. Merge MODE-A's four execution-phase steps (implement-sdd, code-review, test-run, verify) into a single topology-driven implement-verify loop. Extract all inline prompts to separate files organized by mode directory. Enable autonomous progression except where human judgment is explicitly required.

## Acceptance Criteria

- [ ] MODE-A has 6 steps: req-create → req-approve → brainstorm → write-plan → implement-verify → finish
- [ ] MODE-A implement-verify step uses topology-sorted parallel subagent dispatch with TDD, review loops, unified testing, and evidence collection (max 5 rounds)
- [ ] MODE-B structure unchanged (7 steps) but all prompts in separate files
- [ ] All 13 prompt files organized in mode-a/ and mode-b/ subdirectories, written in English
- [ ] All prompt content uses English
- [ ] No inline prompts remain in any TOML file
- [ ] write-plan step includes subagent-driven plan-spec consistency review (state_set:review_plan_spec_consistency_passed)
- [ ] implement-verify gate: command_success:{test_command} + file_exists:docs/evidence/EVIDENCE-{run_id}.md
- [ ] Autonomous progression except req-approve (human), brainstorm (human), debug-question (human after 3+ failures)
- [ ] No engine changes required (no new gate types, no TOML schema changes)
- [ ] All existing tests pass
- [ ] E2E test fixtures updated
